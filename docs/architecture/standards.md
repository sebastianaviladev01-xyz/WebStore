# Estándares de arquitectura y desarrollo

Reglas transversales y verificables de WebStore. Cada regla tiene un identificador `STD-NN` para citarla desde especificaciones, tareas, PR y ADR.

Cuando una regla ya está desarrollada en otro documento, aquí se enuncia en una línea y se enlaza el documento dueño: el detalle no se duplica.

**Niveles:**

- **Obligatoria:** se cumple en el ámbito indicado.
- **Recomendada:** valor inicial preferido; elegir otra opción exige explicarla.
- **Prohibida:** práctica no admitida.
- **Condicionada:** se activa cuando ocurre el disparador indicado.

Una desviación requiere una [excepción registrada por ADR](../development/exceptions.md). Una excepción no permite secretos ni acceso indebido.

## Contratos y políticas por feature

El contrato vigente es el del BFF de prueba ([`BFF-CONTRACT.md`](../../backend/docs/BFF-CONTRACT.md)). Sus rutas y campos se quedan en inglés ([ADR-0024](../adrs/0024-dejar-en-ingles-el-vocabulario-interno-y-el-contrato.md)), y los nuevos siguen esa convención. Nombres de recursos, errores de negocio, paginación y límites nuevos se fijan en la especificación de cada feature: este documento no inventa entidades ni endpoints.

Una operación que se pueda reintentar (por ejemplo, el checkout) declara qué identifica la petición y cómo se tratan los duplicados antes de permitir un reintento automático.

No registrar contraseñas, tokens de sesión o de pedido, códigos de verificación ni datos personales en logs ni en la evidencia de un PR.
